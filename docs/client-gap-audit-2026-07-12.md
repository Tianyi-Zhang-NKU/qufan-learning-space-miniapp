## 已发现的具体问题

1. 媒体上传未落到真实存储：`services/api.js` 的 `uploadFeedbackImage`、`uploadFeedbackVoice`、`uploadFeedbackFile` 使用 `mediaPlaceholder` / `optionalFilePlaceholder` 生成本地元信息。图片、录音、PDF/Word 不会进入对象存储，也无法跨设备可靠访问。
2. 错题本导出不是实际文件：导出接口返回可打印的 Mock 文件描述，不产生 PDF 或 Word 二进制文件、下载地址和打印版式。
3. 登录和数据均不持久：`services/config.js` 当前为 `apiMode: 'mock'`、`authMode: 'mock'`，重启或切换真实模式后现有操作不能保留。
4. 直播入口不能打开真实 ClassIn：当前地址为示例域名，`openClassIn` 只显示提示框。
5. 助教协作没有身份、权限和审计模型：无法知道谁上传了照片、谁补了语音、谁确认了通关，也不能保证主讲与助教并发编辑的结果。
6. 视觉验收尚未完成：自动脚本通过，但尚无微信开发者工具 375px 和真机逐页截图记录，不能确认长文本、按钮、语音条和底部导航在真实容器内无溢出。

## 剩余工作分组

### A. 下一轮给甲方演示前（先做）

1. 用 200 名学生、长评语、多图、多错题数据复测老师网格、待办、学生端进度和错题本页面。
2. 在微信开发者工具逐页验证 375px、常用 Android 宽度和 iPhone 安全区，保留截图作为验收证据。
3. 与甲方一次确认四项产品决策：最终模块名、视频是否保留、错题导出优先 PDF 还是 Word、通关证书视觉与规则。

### B. 上线最小闭环（甲方接口到位后）

1. 建立后端/云函数和数据库，替换 `mock-db.js` 的读写。
2. 接入微信手机号授权或短信登录，维护学生、教师、管理员手机号映射。
3. 接入报名/教务同步：全量初始化、插班/调班/退班增量事件、幂等与失败告警。
4. 接入对象存储及临时签名 URL：图片预览/下载、语音播放、文档预览、权限与至少六个月保留策略。
5. 在服务端生成错题 PDF/Word，并按课程/课次输出可下载、可打印的单文件。
6. 对接 ClassIn 服务端签名入口，禁止在小程序前端暴露 secret。

### C. 第二阶段增强

1. 助教协作方案：共享主讲号或独立助教身份，支持多端会话、操作审计、并发编辑冲突处理。
2. 正确率和班级位置自动计算。
3. 教师待办按课程/课次筛选、提醒与批量处理；大班级性能压测。
4. 课程/学期级证书模板、发放记录、下载与撤销机制。

## 推荐实施顺序

1. 完成微信开发者工具/真机视觉验收，修复发现的交互问题。
2. 等甲方确认导出格式、视频策略、证书规则和助教登录方案。
3. 收到真实接口资料后，按“认证与数据同步 -> 媒体存储 -> 错题文件导出 -> ClassIn”顺序替换 Mock。
