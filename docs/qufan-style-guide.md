# 趣帆学习空间 小程序前端风格基线

本项目当前视觉目标调整为“浅纸感管理风”：页面像一套可直接发布的教培管理小程序，信息密度清晰，卡片安静克制，入口、状态和指标突出但不喧宾夺主。

真实验收请配合 `docs/qufan-visual-acceptance.md`，必须用微信开发者工具截图确认，不能只看代码判断完成。

## 视觉关键词

- 浅纸感管理风
- 米灰页面背景
- 象牙白卡片
- 深蓝主文字
- 低饱和浅绿 / 浅蓝 / 浅橙 / 浅紫图标底
- 小面积橙色、蓝色、绿色强调
- 清晰指标区、短列表入口、状态标签、筛选 Tab 和进度条
- 克制、真实、可发布、偏运营管理工具的移动端界面

## 资源基线

小程序已有背景和图标资源放入 `assets/images/` 与 `assets/icons/`。本轮视觉不删除旧资源，优先通过背景色、透明度和容器样式弱化旧的装饰感。

- `z-auth-bg.jpg`：登录页背景资源，登录页通过浅色遮罩转为发布态背景。
- `z-bg-dark.jpg`：保留为兼容资源，不再作为主要深色视觉。
- `z-bg-light.jpg`：浅色纸面背景资源，可通过 `z-bg` 低透明度铺底。
- `assets/icons/*.svg`：底部导航、课程、直播、错题、媒体等入口统一使用本地矢量图标。

背景资源必须通过 `components/z-bg` 渲染，不要在 WXSS 中直接写本地 `background-image`。

## 页面结构

每个一级页面应包含：

1. `.qf-page` 或 `.screen` 根容器。
2. `<z-bg />` 背景装饰组件，登录页使用 `<z-bg mode="auth" />`，常规页面可使用默认或 `mode="light"`。
3. 普通功能页头部优先使用 `<z-page-head kicker="" title="" desc="" />`，已有页面可继续使用现有 `.qf-top` 结构。
4. 容器卡片使用 `<z-card />` 或全局 `.qf-card`，章节标题、筛选、指标、状态、列表优先使用现有共享组件。
5. 页面信息结构参考“指标区 + 筛选/搜索 + 短列表/短卡 + 状态标签/进度条”的节奏，不做营销页式大 hero。

## 导航

- 底部导航使用 `qf-role-tabbar`；保留 `custom-tab-bar` 作为兼容入口时，两者视觉必须统一。
- 底栏必须左右贴边铺满，不保留两侧空隙。
- 底栏图标使用本地 SVG 矢量图，不使用汉字代替图标。
- 家长/学生端底栏保留：首页、课表、我的；学习反馈不再作为独立底栏页面。
- 页面底部需要保留足够空白，避免内容被自定义 tabBar 遮挡。

## 页面节奏

- 登录页只保留正式登录表单和一个小型调试账号入口，不展示调试步骤或大块演示账号说明。
- 家长/学生端课程首页的课表摘要一次只显示约 3 行，超出滚动。
- 课前练习、课后巩固、课程直播保留入口语义，但视觉调整为浅底按钮或浅色卡片，小面积用橙、绿、蓝强调。
- 个人主页中的“我的课表”直接嵌入课表信息，避免只放跳转卡片。
- 教师个人主页显示今日课程提醒，课程合集页保留“课次路径”和“学生路径”两条录入路线。
- 管理端列表以搜索、下拉筛选、状态标签和短卡为主，教师默认按创建时间排序并可按学科筛选。

## 禁止回退

- 不回到深色大面积玻璃背景。
- 不使用高饱和大色块铺满按钮或卡片。
- 不使用蓝紫渐变、营销风 hero、通用宣传页首屏。
- 不把功能入口做成杂乱彩色九宫格。
- 不用汉字作为底部导航图标。
- 不在页面里写大段调试、解释或占位文案；默认账号等必要调试信息只放小入口。

## 小程序兼容约束

- 背景装饰优先使用 `z-bg` 的 `<image>` 层，避免在 WXSS 里写本地背景图。
- 不引入新的 UI 库和复杂依赖。
- 避免新增破坏兼容性的复杂布局；已有 flex 布局优先保留。
- 关键品牌标识统一使用 `components/z-logo` 或现有登录页品牌结构。
- 标准功能页头部、卡片、指标、状态、列表优先走共享组件和全局样式。
- 固定宽高、flex 居中、按钮、图标、时间胶囊优先使用 `view` / `navigator`，不要用 `text` 承载复杂盒模型。
- 不能只看代码判断完成，必须用微信开发者工具截图对比。
