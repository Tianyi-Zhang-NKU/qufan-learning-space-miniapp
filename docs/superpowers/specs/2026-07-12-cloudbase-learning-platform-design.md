# 趣帆学习平台 CloudBase 架构设计

## 目标

将当前本地 Mock 小程序演进为“学生/教师/管理员小程序 + 教研电脑后台”共享数据的平台。教师手机端只处理课堂小测、本讲总结、错题勾选与通关；教研人员维护可复用的资料包；管理员只查看通关看板、重点关注学生和授权范围。

## 范围

本设计实现本地 Mock 可验证的领域模型、权限规则、小程序页面与 Web 教研后台骨架，并提供 CloudBase 对接契约。真实微信手机号授权、教务系统 API、ClassIn API、对象存储和 PDF/Word 文件生成在甲方提供参数后替换相应适配器，不在前端保存任何密钥。

## 目标架构

```text
微信小程序
  学生/家长 | 教师 | 超级管理员 | 分级管理员
                   |
              领域 API 适配层
                   |
    Mock Adapter <-> CloudBase Adapter <-> HTTP Adapter
                   |
云数据库 / 云函数 / 云存储              CloudBase 静态托管
                                          |
                                    教研电脑后台
```

小程序与教研后台只调用 API，不直接读取数据库。所有跨身份访问、统计和导出都由云函数或服务端 API 执行。

## 领域模型

### 用户、身份与授权

- `users`：以手机号为唯一标识，保存昵称、头像和状态。
- `userRoles`：一个用户可有 `parent`、`teacher`、`admin`、`researcher` 等多个身份，每个身份可关联学生或教师档案。
- `adminGrants`：超级管理员为一个手机号授予 `gradeScopes` 与 `subjectScopes`；空数组表示全范围。分级管理员读取数据时必须匹配两类范围。
- `activeRole`：会话中明确选择的当前身份。家长、教师、管理员数据查询都必须以此身份重新鉴权。

### 通关和重点关注

- 继续以 `lessonFeedbacks` 中 `feedbackType: 'general'` 且 `passed: true` 作为兼容的通关事实来源；页面不暴露该反馈类型。
- `passStatistics` 由 API 动态汇总，不在多个页面分别计算。
- 统计覆盖课程、课次、年级、学科、教师、学生，均使用“已通关学生数 / 应确认学生数”。
- `studentAttentionNotes` 保存管理员人工备注、状态和更新时间。
- 自动规则：连续 2 次已结束课未通关，或累计通关率低于 60%，标记为 `needsAttention`；累计通关率不低于 90% 且至少完成 3 讲，标记为 `excellent`。规则以配置对象提供，后续可由甲方改阈值。

### 教研资料库

- `materialPackages`：年级、学科、学期、课次主题、版本、草稿/已发布状态和原始资料文件。
- `materialUnits`：资料包内可被老师勾选的最小单元。`unitType` 为 `standalone` 或 `group`；阅读理解、长材料使用 `group`，保留完整上下文。
- `materialPublishScopes`：资料包发布到年级、学科、课程或平行班范围。
- `courseMaterialBindings`：将资料包的确定版本绑定到课程/课次，保证历史错题本引用的资料版本不被覆盖。
- 第一阶段不自动拆分 Word/PDF。教研人员手动确认题目单元，避免跨学科自动拆题错误。

## 页面职责

### 小程序

- 学生端：展示下一次课、课堂小测、本讲总结、通关进度和荣誉。排课明细收起，课次标签有滑动提示。
- 教师端：首页先显示待办和未处理数量；反馈只保留课堂小测、本讲总结；通关是顶部独立操作；展示班级/课次通关率。隐藏题目上传、课程改名和直播入口。
- 管理端：首页为年级-学科-教师通关数据看板和重点关注学生；授权管理仅对超级管理员展示。教务写操作、教室合集和全校课表移出主导航。

### 教研 Web 后台

- `资料包列表`：按年级、学科、学期、发布状态过滤。
- `资料包编辑`：上传原始文件、创建/排序题目单元、设定整题或子题、版本发布。
- `发布范围`：发布到课程或同年级同学科的平行班。
- `访问控制`：教研人员只能维护授权范围内资料；管理员可审核、发布、撤回。

## 外部适配契约

### 教务只读同步

- 导入学生、教师、课程、课次、课程成员关系及状态。
- 外部系统是报名、转班、退费的唯一写入方；小程序只消费全量快照或增量事件。
- 每条同步事件带 `sourceEventId`、`occurredAt`、`entityType`、`entityId`、`operation`、`payload`，以 `sourceEventId` 幂等。

### ClassIn

- 课次使用 `courseId`、`teacherId`、`sessionId` 定位，不依赖教室手工映射。
- 云函数按当前身份验证观看权限，调用甲方服务生成短时有效入口。
- 小程序只接收入口 URL、有效期、状态和可播放地址，不接触 ClassIn secret。

## 验收标准

1. 任一统计数字在教师、管理员和学生进度中使用同一通关事实并可被测试复现。
2. 分级管理员无法通过 API 或页面读取授权范围外的课程、学生、统计和资料。
3. 教师端没有通关确认 tab、题目上传、课程改名和直播主入口，但能确认通关、查看待办和勾选已发布题目。
4. 管理端可以查看年级、学科、教师维度通关率，处理重点关注学生备注。
5. 同一资料包可发布给多个平行班，历史错题记录仍引用原版本。
6. 真实外部服务缺失时，Mock Adapter 保持完整可演示链路；替换 CloudBase/HTTP Adapter 不改变页面调用方式。

## 风险与控制

- 不在第一期做自动 Word/PDF 拆题；先让教研人工确认单元。
- 不在小程序内实现报名、调班、退费写操作。
- 不提交媒体、密钥、真实学生数据或 CloudBase 私密配置。
- 页面视觉以现有浅纸感系统为基础，先收敛信息架构后再进行组件级视觉验收。
