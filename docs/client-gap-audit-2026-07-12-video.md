# 基于 2026-07-12 验收录屏的项目差距清单

## 当前项目定位

当前代码库是一个以 `services/mock-db.js` 为数据源的学习闭环 Demo。它已经完成上一轮会议中的课堂小测、本讲总结、错题勾选、通关待办、荣誉、头像网格等基础页面，但本次会议收敛后的产品架构和权限模型尚未实现。

## 已有能力

| 能力 | 当前实现 | 结论 |
| --- | --- | --- |
| 课堂小测/本讲总结 | 学生与老师端均有页面和 Mock API | 可继续保留；需修复小测路由正确性与页面层级。 |
| 图片、文档、语音反馈 | 教师反馈页有选图、选文档、录音；学生页可内联查看 | Demo 可演示；文件仍未接入真实存储。 |
| 通关、待办、荣誉 | `getTeacherTodos`、`confirmStudentPass`、`getStudentHonors` 已实现 | 可作为新看板的核心数据来源。 |
| 错题勾选/导出 | 现有题目框、错题勾选、PDF/Word Mock 导出 | 方向需调整为教研电脑端资料库，真实导出尚未实现。 |
| 管理端教务操作 | 有课程、学生、教室、插班/调班/退班的 Mock 管理页 | 与甲方新决策冲突，应改为只读同步与数据看板。 |
| 登录与角色 | 固定手机号 Mock 登录，单一角色会话 | 与微信手机号授权、多身份选择、分级权限不匹配。 |
| ClassIn | 示例 URL 和预留播放页 | 没有真实签名、课程 ID/老师 ID/课节 ID 对接。 |

## 推荐实施顺序

1. 先完成学生端、教师端的 P0 交互收敛：小测路由、首页信息层级、教师两类反馈、待办红点、班级通关率，形成下一轮可演示版本。
2. 将教师题目上传、课程改名、教师直播等与新方向冲突的入口隐藏，避免下一轮继续演示错误工作流。
3. 先写《教务系统只读同步接口需求》和《ClassIn 接口需求》，交甲方技术负责人确认后再启动真实后端集成。
4. 实现管理员数据看板、重点关注学生和权限模型；这三项应共用同一份服务端数据与授权规则，不能继续堆在 Mock 页面上。
5. 秋季试点前确定一个年级、一个学科，导入该范围的真实数据和教研资料，完成全流程验收。
